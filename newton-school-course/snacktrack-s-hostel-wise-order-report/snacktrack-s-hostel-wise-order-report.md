## Problem Statement

Scenario

SnackTrack&#39;s ops intern was asked to build a hostel-wise order report for management. Working late and in a hurry, they pulled the query together from an old template for a different report &mdash; and never fully swapped out the old table and column names for this database&#39;s actual schema.

The query also has a couple of habitual typing slips, doesn&#39;t account for how messily the status field gets entered in practice, and is missing two things management explicitly asked for.

Query Objective

For each hostel block, show:

 * how many delivered orders it has (order_count),

 * the average order amount, rounded to 2 decimal places (avg_order_value).

Count only delivered orders, for blocks whose average order amount exceeds ₹150.

A handful of orders come from off-campus delivery requests with no hostel block on file. These should still appear in the report, grouped together under the label &#39;Unassigned&#39; rather than left blank.

Sort the final report by avg_order_value in descending order, so that hostel blocks with higher average order amounts appear first.

Data Description

The table is hostel_orders and contains the following data:

 * Inconsistent casing in status: A delivered order might be recorded as &#39;Delivered&#39;, &#39;DELIVERED&#39;, or &#39;delivered&#39;. All three refer to the same real-world status.

 * Missing amount values: A few delivered orders don&#39;t have an amount recorded yet, since billing hasn&#39;t been finalised for them.

 * Missing hostel_block values: A few delivered orders have no hostel block on file at all, since they were off-campus deliveries.

## Solution

```js
--correct the query 
SELECT
COALESCE(hostel_block,'Unassigned') as hostel_block,
count(order_id) as order_count,
round(avg(amount),2) AS avg_order_value 
FROM hostel_orders
WHERE 
lower(status) ='delivered' 
GROUP BY
COALESCE(hostel_block,'Unassigned')
 HAVING
  AVG(amount) > 150 
 ORDER BY avg_order_value desc;
```
